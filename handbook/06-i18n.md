# 06 — Internationalization

Locales: `en` `ar` `zh` `es` `fr` `de`. Default `en`, `localePrefix: "as-needed"` (`i18n/routing.ts`). Arabic is RTL (`dir` on `<html>` in `app/[locale]/layout.tsx`).

## Two copy stores (do not mix)

Merged in `i18n/request.ts`:

```ts
messages: { ...uiMessages, ...contentMessages }
```

| Store | Path | Namespaces (examples) | Used for |
|---|---|---|---|
| UI chrome | `messages/{locale}.json` | `common`, `nav`, `footer`, `search` | Buttons, nav, footer legal, search overlay |
| Page copy | `lib/i18n/content/{locale}/*.ts` | `home`, `about`, `facility`, `facilityMap`, `careers`, `productsHub`, `productCategories`, `impact`, … | Headlines, body, section eyebrows |

`lib/i18n/content/{locale}/index.ts` must export every content module. Adding a new content file means adding it to **all six** locale indexes.

## Rules that prevent `MISSING_MESSAGE`

1. A `useTranslations("footer")` key **must** exist in **all six** `messages/*.json` files under `footer`.
2. Prefer **reusing content namespaces** for section labels in the footer (e.g. `facilityMap.heading.eyebrow`, `careers.openRoles.title`) so labels stay in one place.
3. Do not add a top-level content export named `footer`, `nav`, or `common` — it would overwrite the JSON object.
4. New UI string → all six JSON files. New page sentence → all six `lib/i18n/content/{locale}` files.
5. After adding JSON keys, if the dev server still reports missing keys, restart `npm run dev` (JSON imports can cache).

## How to add a string

**Chrome (e.g. a footer legal label)**

1. Add the key to `messages/en.json` and the other five locale files
2. `useTranslations("footer")` / `getTranslations("footer")`

**Page copy (e.g. a new manufacturing overview line)**

1. Add to `lib/i18n/content/en/facility.ts`
2. Translate in `ar` `zh` `es` `fr` `de`
3. `getTranslations("facility")` on the server page

## Server vs client

- Pages under `app/` are usually **server** components: `getTranslations` from `next-intl/server`, and `setRequestLocale(locale)`.
- Client islands (`Footer`, `Navbar`, `FacilityMap`): `useTranslations`.
- `generateMetadata` should `prepareLocale(params)` (`lib/i18n/prepare-locale.ts`) so metadata matches the URL locale.

## Links

Always `@/i18n/navigation` `Link`. Hash objects:

```ts
{ pathname: "/about" as const, hash: "history" }
```

## Metadata copy

SEO titles/descriptions also exist under `lib/i18n/content/{locale}/metadata.ts` and `lib/seo/config.ts`. If you change a page purpose (e.g. remove leadership), update both so search snippets do not advertise a missing section.
